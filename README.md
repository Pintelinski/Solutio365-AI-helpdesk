# Solutio365-AI-helpdesk

Internship project where I need to make an open-source AI agent that will handle low complexity support tickets with automated replies handling the initial communication exchange to reduce response time and reduce unnecessary mailing back and forth.

## How It Works

```
Tenant email -> Freshdesk ticket created
     -> Freshdesk Automation triggers a webhook to this app
     -> App acknowledges immediately (202), then in the background:
         - fetches the full ticket + any attachments/inline images via the Freshdesk API
         - embeds the ticket text and retrieves similar known issues from Chroma
         - asks the local AI model (via Ollama) to classify the ticket and draft a reply,
           using the retrieved reference material and any attached images
         - posts the reply back to Freshdesk and assigns the ticket to the AI agent
           or a human employee, depending on the classification
```

## Features

- Freshdesk webhook receiver (FastAPI), authenticated separately from the Freshdesk API key
- Local, self-hosted AI model via [Ollama](https://ollama.com) - no data leaves your own server
- Ticket classification into four categories: needs more info, self-resolvable, needs
  human escalation, or unrelated to WiFi/internet
- Reads image attachments and inline pasted images (e.g. router photos, speedtest
  screenshots) and factors them into the diagnosis
- Semantic knowledge base ([Chroma](https://www.trychroma.com/)) of known issues,
  matched by meaning rather than exact wording - see [Knowledge Base](#knowledge-base)
- Public reachability via [ngrok](https://ngrok.com) (temporary; a reserved domain or
  alternative is planned for production)

## Code Setup

1. Install the dependencies:

```
pip install -r requirements.txt
```

2. Copy the environment variable template and fill in real values:

```
cp .env.example .env
```

See [Environment Variables](#environment-variables) below for what each one does.

3. Pull the AI model and the embedding model via Ollama:

```
ollama pull qwen3.5:9b
ollama pull nomic-embed-text
```

4. Load the knowledge base into Chroma (re-run this any time `knowledge_base.json` changes):

```
python chroma.py
```

5. Start the webhook server:

```
uvicorn freshdesk_agent:app --host 0.0.0.0 --port 8085
```

On startup this prints a public ngrok URL - set this (plus `/freshdesk-webhook`) as the
target URL in your Freshdesk Automation Rule, with Basic Auth using `WEBHOOK_USERNAME`
and `WEBHOOK_PASSWORD` from your `.env`.

## Knowledge Base

Known issues live in `AI-classification-setup/knowledge_base.json` as a list of entries:

```json
{
  "id": "wifi_slow_generic",
  "category": "wifi_info_needed",
  "description": "Tenant reports slow WiFi with no further diagnostic details provided yet.",
  "guidance": "Ask for a speedtest screenshot, address, and IP address before diagnosing further."
}
```

When a ticket comes in, its text is embedded and compared against every entry's
`description` - the closest matches (by meaning, not exact wording) are pulled in as
reference context for the AI model. This means new phrasings of an existing problem
are usually recognized automatically, without needing an entry for every possible way
a tenant might describe it.

**To add a new known issue:** add an entry to `knowledge_base.json`, then re-run
`python chroma.py` to load it in. No code changes needed.

Valid `category` values: `wifi_info_needed`, `wifi_resolved`, `wifi_escalate`, `other`.

## Environment Variables

| Variable | Purpose |
|---|---|
| `FRESHDESK_DOMAIN` | Your Freshdesk subdomain (e.g. `yourcompany`) |
| `FRESHDESK_API_KEY` | Freshdesk API key, used for outgoing calls (fetching tickets, posting replies) |
| `FRESHDESK_PASSWORD` | Optional; Freshdesk accepts any value here when using an API key |
| `SUPPORT_AGENT_ID` | Freshdesk agent ID the ticket is assigned to when the AI resolves/handles it |
| `SUPPORT_EMPLOYEE_ID` | Freshdesk agent ID a ticket is assigned to when escalated to a human |
| `WEBHOOK_USERNAME` / `WEBHOOK_PASSWORD` | Basic Auth credentials *you* choose, entered in the Freshdesk Automation's Authentication field - separate from the Freshdesk API key, protects this app's own webhook endpoint |
| `NGROK_AUTHTOKEN` | Your ngrok account authtoken |
| `NGROK_DOMAIN` | Optional; a reserved static ngrok domain, if you have one |
| `OLLAMA_HOST` | URL of the Ollama server (e.g. `http://localhost:11434` if running on the same machine) |
| `OLLAMA_MODEL` | Which model tag to use for classification (e.g. `qwen3.5:9b`) |

## Server Setup

1. Install Linux Ubuntu 24.04 LTS server (Tip: setup OpenSSH for easy command copy and paste)

2. Make your Ubuntu ready to be configured:

```
sudo apt update && sudo apt upgrade -y
```

3. Install Ollama (AI agent model runner):

```
curl -fsSL https://ollama.com/install.sh | sh
```

4. Check if Ollama installed correctly:

```
systemctl status ollama
```

5. Check <https://ollama.com/library> for your desired AI model and note down its tag.
   This project currently uses `qwen3.5:9b` for classification/replies and
   `nomic-embed-text` for the knowledge base embeddings.

6. Pull your desired model(s) and test one directly:

```
ollama pull qwen3.5:9b
ollama run qwen3.5:9b
```

7. Install python essentials on the server:

```
sudo apt install python3 python3-pip python3-venv -y
```

8. Make your directory, clone the repo, and set up the environment:

```
mkdir ~/<your-directory-name>
cd ~/<your-directory-name>
git clone https://github.com/Pintelinski/Solutio365-AI-helpdesk
cd Solutio365-AI-helpdesk
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env   # fill in your actual environment variables
```

9. Pull models and seed the knowledge base:

```
ollama pull qwen3.5:9b
ollama pull nomic-embed-text
python chroma.py
```

10. Run the app:

```
uvicorn freshdesk_agent:app --host 0.0.0.0 --port 8085
```

## Known Limitations / Next Steps

- Not yet running as a systemd service, so it stops if the SSH session/process ends
- ngrok URL is not yet a reserved static domain
- No automated cleanup of downloaded attachment images once a ticket is resolved
- Knowledge base currently covers WiFi/internet issues; other issue types route to a
  human by default and are not yet covered by dedicated classification logic
